# khaiminov.com — спека и контекст проекта

Живой документ. Ведём его в репозитории, чтобы контекст переживал переезд
между компами/аккаунтами. Правь свободно, секции ниже — не догма.

## Идея

Личный сайт (карьера + человек за ней). Метафора: **стена с гирляндой
тёплого света**, под гирляндой на стене — фотографии (на скотче или висят
на нитке/прищепке). Главная — пять "фото" на стене: Карьера, Проекты, Блог,
Личное, Контакты. Переход в раздел — та же стена, но уже с фото по месту
работы/теме. Клик по фото — экран "подробнее" (стори): несколько фото +
текст истории.

Цветовая гамма не жёстко закреплена (стена — не обязательно фиолетовая),
но за основу взяли текущий бренд-акцент (тёмный сливовый фон + тёплая
бронза/золото гирлянды) — можно менять.

## Технические решения

- **Стек:** основной сайт — plain HTML/CSS/JS, без сборки, без бэкенда/API
  (см. `wrangler.jsonc` и раздел "Cloudflare" ниже). Осознанный выбор, не
  временная мокап-стадия — миграция на генератор не планируется, у сайта
  нет столько контента, чтобы сборка себя окупила. Блог (ниже) собирается
  отдельно, через Astro — там как раз нужны markdown-коллекции и генерация
  страниц.
  - **Структура репо:** сайт живёт в `/apps/site` (`index.html`,
    `style.css`, `app.js`, `assets/`, `version.json`, `_headers`).
    `wrangler.jsonc` остаётся в корне репо (там его ищет Cloudflare
    Workers Builds) и просто указывает `assets.directory: "./apps/site"`.
    Блог — отдельно, `/apps/blog` (свой `wrangler.jsonc`, свой Cloudflare
    Workers Builds проект с root directory `apps/blog`). `docs/` — не
    деплоится, вне `assets.directory`, живёт в корне.
- **Cloudflare — как реально настроено (Workers Builds):**
  - Git-репозиторий подключён напрямую (без своего `.github/workflows`,
    билдит сам Cloudflare).
  - **Deploy command** (для продакшен-ветки `main`): `npx wrangler deploy`
    — сразу загружает и переключает трафик.
  - **Version command** (для всех остальных веток, "Builds for
    non-production branches" включена): `npx wrangler versions upload` —
    только загружает версию с отдельным preview-URL, `khaiminov.com` не
    трогает. Это осознанный дизайн Cloudflare, не баг — обе команды разные
    и настроены правильно.
  - Каждый non-production билд даёт две ссылки в логе: Version Preview URL
    (уникальный по ID версии) и Version Preview Alias URL вида
    `https://<ветка>-khaiminov-com.<account>.workers.dev` — по алиасу
    удобнее всего смотреть текущий стейт конкретной ветки.
  - `wrangler.jsonc` в корне репо обязателен — без него билд падает с
    "Missing entry-point to Worker script or to assets directory".
    `assets.directory` указывает на `./apps/site` (см. выше).
- **Локализация (ru/en):** один шаблон + словари переводов, переключатель
  ru/en на клиенте поверх объекта с контентом (`apps/site/data.js`,
  `apps/site/app.js`). Тексты частично переводит Клод, но должна быть
  возможность править вручную (просто текстовый файл — легко).
- **Фото:** сжимаются заранее (resize + WebP) и коммитятся уже лёгкими.
  Автоматизацию через Actions пока не делаем — сложность не нужна при
  таких объёмах.
- **Хостинг:** Cloudflare Pages, бесплатный тариф (уже настроен на
  `khaiminov.com`, см. `_headers` в корне).
- **Блог:** `/apps/blog` в этом же репозитории (не отдельный репо),
  свой Cloudflare Workers Builds проект, поддомен `blog.khaiminov.com`.
  С главного сайта — просто ссылка (карточка на стене), без интеграции
  контента. Подробности — в разделе "Блог" ниже.
- **Почта на `khaiminov.com`:** отдельная задача, не блокирует мокап.
  На момент разговора похоже, что Cloudflare free tier не даёт email
  routing/hosting в нужном виде — надо перепроверить и настроить отдельно.
- **CV:** будет лежать в разделе "Контакты" (кнопка скачивания). Файл
  `cv.pdf` пока не в репозитории — возьмём финальную версию у Алексея
  (есть `Alexey_Khaiminov_CV.pdf` / `Khaiminov_Resume_RU.pdf` на его
  Desktop, но это черновики для генерации сайта, не обязательно то, что
  ляжет на сайт как есть).

## Layout

Двухколоночная схема на каждой странице:
- **Слева** — постоянное меню (Карьера / Проекты / Блог / Личное /
  Контакты), подсвечивает активный раздел.
- **Справа** — "стена" с гирляндой сверху и фото-карточками
  (полароид на нитке/скотче).
- **Синхронная подсветка**: на главной наведение на пункт меню подсвечивает
  соответствующую карточку на стене и наоборот (`data-sync` + классы
  `.is-synced` в `app.js`). Внутри разделов (Карьера и т.д.) меню слева
  просто показывает активный верхнеуровневый раздел, без дублирования
  списка компаний/проектов слева — второй список показался бы избыточным.
- **Клик по карточке** → оверлей "стори" (несколько фото + текст). Работает
  универсально для Карьеры/Проектов/Личного через одну функцию
  `openStory(collection, id)`.
- **Мобильная адаптация**: на ширинах ≤860px левое меню превращается в
  горизontальную прокручиваемую полосу под шапкой (без гамбургера — проще и
  надёжнее). Карточки перетекают в 1 колонку на самых узких экранах.
- **Иллюстрация стены/гирлянды**: под рукой нет инструмента генерации
  изображений (DALL-E и т.п.), поэтому стена и гирлянда — это проработанный
  SVG/CSS (шум на стене через `feTurbulence`, лампочки — радиальные
  градиенты с двойным свечением и мерцанием). Если понадобится
  "настоящая" сгенерированная картинка — нужно принести файл извне и
  вставить как фон.

## Статус

Структура разделов и их содержание — смотри актуальные на самом сайте,
здесь не дублируем (расходится с реальностью быстрее, чем кто-то успеет
это перечитать).

Основной сайт (`/apps/site`): двухколоночный layout (меню слева / стена
справа) с синхронной подсветкой, кликабельные карточки со "стори"-
оверлеем во всех разделах, RU/EN, мобильная адаптация, футер с версией/
коммитом. Карьера, Проекты, Выступления — реальные данные и фото.
Личное — пока заглушки, содержание позже. Контакты — email/Telegram/
GitHub/CV реальные, LinkedIn добавляется.

Блог (`/apps/blog`): Astro + Markdown-статьи, Decap CMS на `/admin`,
giscus для комментариев — см. раздел "Технические решения" выше и TODO
в `apps/blog/public/admin/config.yml` / `apps/blog/src/components/Giscus.astro`.
Два черновика статей (kts-compiler, MeasureSync). Ждёт: отдельный
Cloudflare Workers Builds проект под свой поддомен, решение по
видимости репозитория для Discussions, OAuth для Decap CMS.

Известные пробелы (не блокируют, но не забыть): почта на домене через
Cloudflare (free tier под вопросом); реальные фото для разделов
"Личное" и "Образование" (новый раздел — университет и сертификаты,
данные взяты с LinkedIn, фото и развёрнутый текст — позже).
